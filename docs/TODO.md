# 六阶段执行清单

使用方式：一次推进当前阶段的一个可验收任务。阶段内无需为常规可逆步骤反复确认；实机与受保护环境操作遵守 AGENTS.md。完成时关联一份报告、更新 STATUS，再推进下一项。

命令来自实际项目和当前环境，不能把本文的任务描述编造成“已经存在的脚本”。需要新代码时在本仓库按需添加，并记录入口。

## P1 硬件连接：保留并复核已有链路

前置：在实验室主机，获得原 EVA 工程位置或启动方式。

- [ ] **P1.1 只读盘点与基线保存。** 确认主机、系统、GPU、磁盘；读取 EVA/SDK 的提交、子模块、本地修改、解释器、VR/硬件启动脚本和配置。记录如何回到原启动方式；不自动备份数据大目录、不输出凭据。
- [ ] **P1.2 现场链路复核。** 按实验室原方式，由现场操作者确认机械臂、夹爪、相机角色、VR 映射、使能/暂停/断连行为；保存一个观测样本和必要日志。不能套用公开默认的主从臂配置。

验收：有可追踪的原版本/修改/环境与恢复说明；原 VR 控制和设备身份经现场确认；样本字段可读取。未实际复核的部分保持未验证。

给 Codex：

> 执行 P1.1，只读盘点原 EVA/VR 工作环境，保存恢复依据并填写本地配置。不要启动硬件。完成后给出 P1.2 所需的最小现场检查步骤。

## P2 环境搭建：新增独立模型环境

前置：P1.1 完成；可以在设备复核之前做纯软件工作，但不得因此标记 P1 已完成。

- [ ] **P2.1 核对候选模型要求。** 初始候选 LingBot-VLA-v2；检查其当前来源、版本、权重、许可、推理/训练依赖和磁盘需求。比较主机资源；如需换模型，说明原因并更新 DECISIONS。
- [ ] **P2.2 安装隔离环境。** 在新目录创建模型环境，固定依赖和上游版本；使用已有驱动，按需下载已授权资产。明确执行路径和进程/端口；避免与原环境共享可修改的安装目录。
- [ ] **P2.3 环境检查。** 验证解释器、依赖、GPU 和模型加载；比较基线，确认没有改动受保护文件。原遥操回归按现场授权执行，安装完成不等于回归通过。

验收：新增环境能独立运行模型加载；资源有余量；原基线及恢复路径保留，回归结果明确。

给 Codex：

> 执行 P2。根据现场盘点为候选模型建立独立环境，记录精确版本和检查命令。不要升级原 EVA 环境、驱动或系统 Python；需要系统修改时先列出必要性和影响。

## P3 模型离线测试：建立观测到动作的接口

前置：P2 模型环境可用；P1 样本可用时优先用真实观测，否则合成输入只用于计算检查。

- [ ] **P3.1 确认接口语义。** 沿 EVA 实际数据流检查 state、图像、action 和时间戳，按 SPEC 记录映射。选择所需最小适配方式；协议名称相同不能代替字段检查。
- [ ] **P3.2 实现必要适配与离线测试。** 首先覆盖关节顺序、夹爪、RGB、动作变换与回合重置；用不会发送硬件指令的接收端检查动作块。根据选定模型测试空输入、NaN、维度错误、超时和旧响应。
- [ ] **P3.3 模型冒烟与基准。** 运行少量连续推理，区分冷启动与稳态耗时，记录显存、输入尺寸、动作长度及有限数值检查。保留至少一个固定样本供以后回归；不据此判断任务成功率。

验收：观测可进入模型，返回动作符合已声明契约；离线测试有实际执行证据，未向实机下发动作。真实样本尚缺失时只能完成合成检查，P4 试采后补验。

给 Codex：

> 执行 P3，构建最小 EVA 到候选模型的适配。所有测试离线，禁用动作输出。输出接口映射、必要代码和实际测试结果，不把基础权重预测视为可部署 YAM 策略。

## P4 数据采集：先试采，再形成训练数据

前置：P1 现场链路已确认；在正式采集前确认唯一任务和成功条件。

- [ ] **P4.1 定义任务并试采 3 条。** 确定操作哪只臂、物体、初始状态、目标区域、指令和成功条件；复用实验室 VR 配置，采集图像、实测状态、实际下发目标及时间信息。保留失败/取消记录的处理规则。
- [ ] **P4.2 逐条质检并回验接口。** 看视频与曲线，检查帧数、时间同步、左右顺序、动作来源、夹爪和标签。用真实样本重跑 P3；缺字段先修配置再采，不能靠猜测补数据。
- [ ] **P4.3 正式采集与冻结数据。** 根据试采确定首批数量和场景变化范围；保留原始数据，记录每条 QC 结果。检查 EVA 输出能否直接供模型读取，只有必要时转换。按 episode 固定训练/验证列表，统计量只用训练集。

验收：明确的数据位置、版本、数量、排除原因和划分；可加载训练样本，图像/状态/动作对应正确；P3 的真实观测检查完成。

给 Codex：

> 执行 P4 的当前任务。先确认具体 pick-and-place 定义，通过 3 条 VR 试采核对数据语义，再决定正式数量。复用 EVA 的保存功能，保留原始数据，只实现必要的质检或转换。

## P5 模型训练：先证明能训练和重载

前置：P4 数据验收；选定模型及数据映射已记录。

- [ ] **P5.1 小规模训练验证。** 补齐该模型实际需要的训练资产，在少量训练 episode 上完成前向、反向、优化、保存与重新加载。记录显存峰值、耗时和 loss；可做小样本过拟合诊断。参数高效微调、冻结或更换算力按实测选择，不能假设 4090 一定装得下。
- [ ] **P5.2 正式微调。** 固定数据版本、映射、训练配置和随机种子，明确步数/停止条件再开始。监控显存、loss 和验证指标，记录失败或中断；不要修改验证集来改善结果。
- [ ] **P5.3 导出并重验。** 将权重、模型版本、数据版本、归一化统计与预处理配置对应保存；在新进程重新加载导出产物，对固定样本重新运行 P3。需要合并适配器时验证合并前后结果。

验收：存在真实训练产物，能独立重载；输入映射和统计与训练一致；训练报告足以复现命令。训练 loss 下降不代表实机成功。

给 Codex：

> 执行 P5 的当前任务。先在小数据上验证完整训练和重载，再提出正式训练配置。记录资源占用与产物绑定关系；无权重或统计缺失时直接报告，不用占位 checkpoint 通过检查。

## P6 模型部署：先检查预测，再受限执行

前置：P5 可重载模型；P1 现场环境复核仍有效；本次现场执行范围已明确。

- [ ] **P6.1 无动作输出验收。** 用录制观测或只订阅观测的模式运行实际部署路径，禁用命令发布；确认帧和反馈时效、动作范围、回合重置、超时、缓冲清空及 VR/策略控制互斥。控制权丢失后不得继续执行旧动作。
- [ ] **P6.2 受限现场试运行。** 现场操作者确认初始姿态、限位、速度、急停和超时后的实际状态。先短动作，再完整任务；发生异常保存日志并停止该次实验，不自动放宽保护重试。
- [ ] **P6.3 固定条件评测。** 提前确定回合数、起始条件和时间上限；完整记录成功、任务失败、干预和基础设施异常，并保存视频。异常不静默替换；未完成计划标 incomplete。固定 run_id，避免覆盖旧回合。
- [ ] **P6.4 收尾与交接。** 明确模型服务/控制节点的启停和恢复到 VR 的步骤；仅停止本次拥有的进程。记录模型、数据、配置版本、指标与失败原因，在 version_history 留简短里程碑。

验收：实际模型通过受限部署检查，固定评测完成并可追溯。若无成功回合或未达预定目标，写明能力尚未达标，回到有证据支持的 P4/P5 改进，不宣称任务成功。

给 Codex：

> 先执行 P6.1，使用真实部署配置验证但禁止动作发布。通过后准备 P6.2 的现场步骤与验收项；实机运动由现场授权范围决定。最终按事先固定的条件评测，保留所有失败和干预记录。
