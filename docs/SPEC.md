# 最小闭环规格

## 已确认

- 平台：YAM 双臂工作站；实验室提供 4090 主机，本地推理和控制。
- 数采：EVA-CLIENT 的 VR 遥操作，用户确认实验室已经验证。
- 模型：可替换，LingBot-VLA-v2 为暂定候选。
- 目标：完成硬件连接、环境搭建、离线测试、数采、训练、部署的一次可复现闭环。
- 开发：Codex 负责代码、配置、离线验证和记录；现场操作按当次明确授权执行。
- 仓库：私有；保留用户指定的最小目录。

## 范围

首版只支持一个工作站、一个明确的 pick-and-place 任务、一个当期选定模型。复用 EVA 的 VR、IK、采集和执行能力，只写缺少的接口与必要脚本。

不建设通用机器人平台、模型榜单、自动科研 Agent、复杂 CI/CD 或独立管理界面。RoboTwin 评测和原云端方案不属于本轮最小闭环。

## 必须保存的现场基线

EVA 和 SDK 的实际路径、提交及本地修改；原环境解释器与依赖记录；VR 启动方式、设备映射、相机角色及现场标定配置。配置副本保存在受控本地位置，仓库报告记录路径和指纹，不泄露凭据。

公开仓库默认值不能代替实验室配置。当前公开 YAM 示例默认偏向主从臂；原启动器可能配置 CAN、标定、运动或复位 USB。读取实际脚本后才确定执行方式。

## 接口约定：先核实，再冻结

以下内容在 P3 初步确认，P4 使用真实 episode 复核。结果填写到配置副本并在报告里记录配置指纹。

| 项目 | 需要记录 |
|---|---|
| state | 字段名、维度、左右与关节顺序、单位、夹爪含义 |
| images | 相机角色和键名、颜色顺序、布局、尺寸、裁剪/缩放 |
| action | 字段名、目标关节/末端位姿、绝对/相对、单位、夹爪范围 |
| time | 图像/状态/命令时间戳、采样频率、对齐规则 |
| transform | 归一化和动作反变换由哪一层执行，确保不重复 |
| runtime | 回合重置、动作块、执行频率、超时、控制权切换和缓冲清空 |

VR 原始手柄位姿与机器人动作不是同一语义。必须追踪实际链路：重定向 → IK → 限制/平滑 → 下发目标。训练 action 使用哪个阶段的目标需明确，不能用测得 state 冒充 command。保留有用的原始字段用于诊断。

在双臂六关节加夹爪配置下，关节策略常用 14 维；实物和字段尚未检查，不能把这个候选维度当作现场事实。末端位姿策略需要另行确认坐标系与旋转表示。

## 数据、训练与评测

- 先采 3 条试采 episode，逐条检查视频、指令、状态、动作和时间同步；通过后再扩大采集。
- 首批成功示教数量在试采后确定，不将固定条数当成效果保证。
- 按完整 episode 划分训练/验证集，记录固定列表；同一 episode 的帧不能跨集合。归一化统计只由训练集计算。
- 保留不可变原始数据；派生版本记录输入版本与处理方式。质量不合格的 episode 留下排除原因，不静默删除。
- 先跑可保存、重载的短训练，再正式训练。模型选择、微调方式和步数按 4090 实测资源确定；不能把“能推理”当作“能训练”。
- 离线误差和训练 loss 仅用于检查，不等于实机任务成功率。
- P6 之前明确任务物体、起始状态、目标区域、成功条件、时间上限和固定评测回合数。人工接管不能计为自主成功。
- 成功、任务失败、人工干预、基础设施异常分别记录；异常不能悄悄换回合。未完成计划时标记 incomplete，不发布为完整评测。

## 最终完成条件

1. 原遥操可恢复；新增环境及控制入口有明确启停方法。
2. 实测观测能进入模型，输出转换后符合硬件接口；命令过期、模式切换和停止行为经验证。
3. 真实数据版本、训练设置、模型权重和部署配置可对应起来并重新加载。
4. 固定条件的完整实机评测已完成，成功数、失败和干预均有证据。若任务目标未达到，记录未达到，不将“流程运行结束”写成“任务能力达标”。

## 暂不假设

实验室目录、操作系统/驱动、EVA 版本、VR 型号、相机型号、CAN 名称、标定值、首个具体任务和最终模型均待相应阶段核实。现在无需为了填写文档猜测这些信息。
